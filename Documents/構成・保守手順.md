# Jitsi Meet 構成・保守手順

この公開版では `meet.example.com` をドメインの設定例として記載しています。操作前に自分のドメインへ読み替え、[公開版セットアップ](公開版セットアップ.md)に従って `JITSI_DOMAIN` を設定してください。検証環境の構成と動作記録を示す文書であり、新規サーバーの一括導入手順ではありません。

対象：`meet.example.com`。構成確認日：2026年11月4日。音声案内の方針更新日：2026年11月5日。サーバー操作はSSHの管理者が実施してください。秘密情報はこの文書には記載していません。

## サービスと通信

追加サービスは `jitsi-ai` ユーザーで実行します。プログラムの所有者はrootで、実行ユーザーは書き換えできません。設定ファイルは `jitsi-ai:jitsi-ai`、モード600です。内部中継トークンは `root:prosody`、モード640です。

追加APIは `127.0.0.1:8765`、Opusプロキシは `127.0.0.1:8766` で待ち受けます。外部へ公開するのはNginxの `/ai/` だけです。内部の `/internal/bridge/` は公開用の中継対象にしていません。

JVBは参加者のOpus音声を追加APIへ送り、追加APIは会議認可と利用上限を確認して公式プロキシへ渡します。プロキシはOpenAIへの送信と、返された通訳音声のOpus化を担当します。参加者は標準のJitsi字幕・音声トラックを受信します。この流れは[Jitsi公式の中継方式](https://jitsi.github.io/handbook/docs/devops-guide/transcription/)に基づきます。

P2P接続は停止しています。2人会議でもJVB経由で音声を取り出すためです。エンドツーエンド暗号化を有効にした会議は、この音声解析・録画の確認対象に含めていません。

`metadata` と `audiotranslation` のXMPPコンポーネントでは、`focus@auth.meet.example.com` を管理者に指定しています。metadataの管理者指定がないと、翻訳先の要求がJicofoへ渡らず、通訳音声が開始されません。

## 管理者のサインインとサインアウト

管理者は `/ai/login` の専用画面からサインインします。従来のユーザー名とパスワードハッシュを継承します。Basic認証は使用しません。管理者画面への未認証アクセスはサインイン画面へ転送し、管理APIはHTTP 401で拒否します。

セッションの有効期間は8時間です。CookieにはSecure、HttpOnly、SameSite=Strictを指定し、セッションのハッシュだけをSQLiteへ保存します。HTTPSが必要です。更新時のテーブル作成は既存の会議・録画・APIキーを保持します。

「サインアウト」は現在のブラウザーのセッションとCookieを削除します。削除前のCookieを再送しても管理APIへアクセスできません。別のブラウザーのセッションは維持します。管理者のパスワードハッシュを変更した場合は、既存の全セッションが無効になります。

## 文字起こしと通訳の初期状態

新規参加時の音声通訳言語はJitsi標準状態の `null`、すなわちオフです。サーバーが音声通訳を利用可能として通知しても、聞き手が言語を選択するまでは音声通訳を要求しません。モデレーターが会議全体を無効にした場合は、参加者の増減で勝手に再有効化しないようにしています。

議事録用の文字起こしは、登録されたAI会議で有効になります。音声通訳をオフにする操作では文字起こしは止まりません。AI会議全体の処理を止める場合は主催者の「AI処理を終了して議事録を作成」を使用してください。

## 日常の状態確認

以下のコマンドは設定の秘密値を表示しません。

```bash
sudo systemctl is-active nginx prosody jicofo jitsi-videobridge2 jibri jitsi-ai jitsi-ai-proxy
curl -fsS https://meet.example.com/ai/api/status
sudo ss -lntp | grep -E ':876[56]'
df -h /srv/jitsi-recordings
sudo nginx -t
sudo prosodyctl check config
```

Prosodyの確認では、既存のcross-domain BOSHに関する案内が残っています。この環境では終了コード2の助言表示と、終了コード1の構文エラーを分けて扱っています。変更後は表示内容と稼働状態の両方を確認してください。

ログを取得する場合は、会議名・発言や接続情報を含む可能性を考慮し、共有前に確認してください。APIキーや内部中継トークンをコマンドの出力に含めないでください。通常運用は警告以上のプロキシログとし、音声・文字起こしのデバッグダンプは無効にしています。

## 記録の保存とバックアップ

録画はJibriの保存処理が終わると `.complete` が作成されます。解析ワーカーはこのマーカーのあるMP4だけを処理します。録画の文字起こしは10分ごとの音声に分割して送信し、文字起こし結果を保存した後に議事録を作成します。議事録だけが失敗した場合は、再実行時に保存済み文字起こしを利用します。

構成バックアップは `/var/backups/jitsi-ai/<timestamp>/configs.tgz` のような日付時刻付きの場所へ保存してください。検証環境ではパッケージ一覧も保存しました。ネイティブ連携の設定前には `native-日付時刻/configs.tgz` を作成します。APIキーを含む設定が入るため、root専用のまま保管してください。

これらは構成変更前のバックアップです。運用中の録画や最新のSQLiteデータを継続的にバックアップする仕組みではありません。運用バックアップでは、設定・SQLite・録画を対象にします。稼働中のSQLiteはオンラインバックアップ機能を使うか、追加サービスを停止してからコピーしてください。

録画や議事録の保存期間・自動削除は設定していません。リンクの24時間という有効期間は、記録の削除期限ではありません。録画の保存量と空き容量を確認し、必要なデータの保管後に管理者が削除してください。

## 追加サービスの更新

この手順は構築済みのサーバーへの更新用です。空のサーバーを一括構築する手順ではありません。会議・録画がない時間に実施してください。サービス更新中はAI接続が切断・再接続されます。

1. ローカルで `python -m pytest -q tests` を実行します。
2. `python ops/package.py` で秘密情報を含まない配布物を作成します。
3. 配布物をSSHで `/tmp/jitsi-ai.tgz` に転送します。
4. サーバーで現在の構成、SQLite、必要な録画をバックアップします。
5. 以下の更新処理を実行します。

```bash
sudo tar -xzf /tmp/jitsi-ai.tgz -C /opt/jitsi-ai --no-same-owner
cd /opt/jitsi-ai
sudo env JITSI_DOMAIN=your-meet.example.org bash ops/deploy.sh
```

`deploy.sh` はAPIキー、SQLite、録画を維持してサービスを更新します。Nginxの構文確認後に追加サービスを再起動します。日本語辞書とWeb用音声案内も再適用します。削除する旧ファイルは、以前のブラウザー専用音声処理と廃止した音声案内ボットのファイルに限定しています。

## Opusプロキシの更新

上流の版はコミットを固定しています。最新のブランチへ自動追従はしません。更新する場合は、採用する版のコード、OpenAIイベント形式、Jicofo/JVBとの互換性を確認してください。

```bash
sudo systemctl stop jitsi-ai-proxy
sudo bash /opt/jitsi-ai/ops/install-native-proxy.sh
sudo systemctl start jitsi-ai-proxy
sudo systemctl is-active jitsi-ai-proxy
```

構築はAPIキーを読めない専用ユーザー `jitsi-proxy-build` で実施します。依存パッケージの自動スクリプトを無効にし、必要なビルドだけを実行します。実行時はroot所有のファイルを `jitsi-ai` が読み込みます。

モデル対応修正では入力言語のヒントを外して自動認識させています。連続音声の文字起こしは約4秒ごとに確定を要求します。また、使っていないWASM形式の音声処理を読み込まないよう、バンドルの遅延読み込みを維持しています。修正内容は `ops/patch-opus-proxy.py` に全文を収録しています。

## 日本語音声案内の更新

台本は `ops/japanese-announcements.json`、元音声は `assets/announcements/*.wav` です。Windowsの日本語音声 `Microsoft Haruka Desktop` で生成しています。APIキーは使用しません。

台本を変更した場合はWindowsで次を実行し、音声を聞いて内容を確認してから配布してください。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ops/generate-japanese-announcements.ps1
```

`ops/install-japanese-announcements.py` は元のWeb音声を `/var/backups/jitsi-ai/english-announcements` に保存し、日本語のMP3とOpusを配置します。ブラウザーに読み込み済みの音声は更新されないため、再参加または強制再読み込みをしてください。公式Android/iPhoneアプリの案内音声はアプリに同梱されています。[iOSの処理](https://github.com/jitsi/jitsi-meet/blob/stable/jitsi-meet_11248/react/features/base/sounds/functions.ios.ts)と[Androidの処理](https://github.com/jitsi/jitsi-meet/blob/stable/jitsi-meet_11248/react/features/base/sounds/functions.android.ts)で確認しています。

## Web版だけの音声案内

2026年11月5日に、音声案内の日本語化をWeb版だけに変更しました。公式アプリは同梱の標準音声を再生します。会議に参加する音声案内ボットと自動起動設定を廃止し、公式アプリの案内を抑止する `disabledSounds` の追加設定も取り除いています。

`ops/use-web-announcements.py` はこの切替を担当します。廃止したボットの設定、内部認証情報、専用のconfig.js分岐、実行用ファイルを除去します。APIキー、管理者認証、モデル設定、会議と録画のデータは保持します。変更前の構成は `/var/backups/jitsi-ai/web-announcements-日付時刻` に保存します。

`deploy.sh` からも同じ処理を実行するため、更新時にボットが再び有効になることはありません。標準の `/config.js` をWebと公式アプリの両方で利用し、音声案内の停止設定を追加しません。現在の設定を読み込むには、参加中のクライアントを一度退出して再参加してください。

## 録画用Chromeの更新

ChromeとChromeDriverは同じ版の組み合わせで固定しています。Chromeだけの自動更新を防ぐためaptのholdを設定しています。ブラウザーの保守更新時は録画を停止し、両方を揃えて更新してから、短い会議で録画開始・停止・MP4保存を確認してください。

`snd_aloop` はロード済みで、自動ロードも設定しています。再起動後にJibriの音声が入らない場合は、モジュール、音声デバイス、Jibriのログを確認してください。

## 構成の復元

復元する場合は、まず復元前の設定・SQLite・録画を退避してください。対象となるバックアップの時刻と中身を確認し、保守時間を設けてから復元します。構成アーカイブの一括展開は、別の作業による変更も上書きするため、そのまま実行する自動コマンドは設けていません。

追加AIサービスだけを止める場合は `jitsi-ai-proxy` と `jitsi-ai` を停止します。通常のJitsi会議は独立したサービスです。入口のNginx転送やWeb用音声の復元も必要な場合は、退避した設定・音声を対象ごとに戻してください。

復元後はNginxとProsodyの構文確認、サービス稼働、会議への参加、音声、録画、API利用範囲を確認してください。
